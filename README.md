# appraisal-system: YouTube アップロード & 映り込みチェックシステム

素材動画をアップロードし、AIによる顔・人物検出で「映り込みの可能性がある区間」を候補として提示、
人間がカット/そのままを選んで確定した動画を YouTube にアップロードするための Web アプリです。

映り込み箇所の**ぼかし処理はこのアプリでは行いません**。YouTube Studio 側の編集機能で対応してください。
このアプリの役割は、映り込みの可能性がある区間を見つけて確認しやすくすること、不要な区間をカットして
動画を仕上げること、そして YouTube へのアップロードです。

**重要**: 自動検出はあくまで候補提示であり、見逃しを保証するものではありません。必ず全編を目視で確認してください(詳細は「検出精度の限界」を参照)。

## Windows での使い方(コマンド操作なし)

1. このフォルダの `起動.bat` をダブルクリックしてください
2. 初回はNode.js・ffmpeg・依存パッケージ・検出モデルの確認/自動インストールが行われます(数分かかることがあります)
3. 準備ができるとサーバーが起動し、自動でブラウザに操作画面が開きます
4. 操作画面の流れ: **素材を選ぶ → 区間判定を確認 → 編集(カット/そのまま) → 完成動画の再生**
5. 使い終わったら、`起動.bat` で開いた黒いウィンドウを閉じるとサーバーが停止します

自動インストールが失敗する場合(`winget` が無い環境など)は、Node.js([https://nodejs.org/](https://nodejs.org/))と
ffmpeg([https://www.gyan.dev/ffmpeg/builds/](https://www.gyan.dev/ffmpeg/builds/))を手動でインストールし、
`起動.bat` を再度実行してください。

YouTube へのアップロード機能を使うには、`.env` に Google OAuth のクライアントID/シークレットを設定する必要があります
(下記「Google OAuth の設定」参照)。設定しなくても、素材の確認・カット編集・完成動画の再生までは操作できます。

## 必要環境(手動セットアップする場合)

- Node.js 20+
- ffmpeg / ffprobe(`PATH` に通しておく)
- YouTube Data API v3 が有効な Google Cloud プロジェクトの OAuth クライアント(Web アプリケーション、アップロード機能を使う場合)

## セットアップ(コマンドで行う場合)

```bash
npm install
npm run download-models   # face-api.js の顔検出モデルをローカルにコピー
cp .env.example .env      # Google OAuth のクライアントID/シークレットなどを設定
npm run dev                # http://localhost:3000
```

### Google OAuth の設定

1. Google Cloud Console でプロジェクトを作成し、YouTube Data API v3 を有効化
2. OAuth 同意画面を設定(テストユーザーとして自分のアカウントを追加)
3. OAuth クライアントID(種類: ウェブアプリケーション)を作成し、リダイレクトURIに
   `http://localhost:3000/auth/google/callback` を追加
4. 発行されたクライアントID/シークレットを `.env` の `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` に設定
5. アプリ起動後、画面右上の「Googleでログイン」からOAuth認証を行う(トークンは `data/tokens/` にローカル保存)

## 使い方の流れ

1. **素材動画をアップロード** — ローカルの動画ファイルを選択してアップロード
2. **AI解析を実行** — 顔・人物検出が非同期で走り、進捗バーが表示される。完了するとタイムライン上に候補区間が表示される
3. **候補を確認** — 候補をクリックすると区間をループ再生できる。「そのまま/カット」を選んで保存
4. **候補にない区間も手動追加** — タイムラインをドラッグすると手動区間を追加でき、候補と同じ処理(カット/そのまま)を選べる
5. **編集を確定して動画を生成** — カット決定を ffmpeg で適用し動画を短縮。カットに伴う時間のズレは自動計算され `edit_log` に保存される
6. **完成動画を確認** — 画面内で再生して結果を確認(映り込みが残っている場合は、この動画を YouTube Studio 側でぼかし編集してください)
7. **YouTube にアップロード** — タイトル・説明・タグ・公開設定を入力してアップロード

## 検出に使っているライブラリと精度の限界

| 用途 | ライブラリ |
|---|---|
| フレーム抽出 | ffmpeg(`fluent-ffmpeg` 経由) |
| 顔検出 | `@vladmandic/face-api` + `@tensorflow/tfjs-node`(SSD MobileNetV1、完全ローカル実行) |
| 人物(体)検出の補助 | `@tensorflow-models/coco-ssd`(person クラス) |

映像データ自体は外部送信されません。ただし `coco-ssd` の学習済みモデルの重み(映像内容とは無関係な汎用パラメータ)は
初回起動時に TensorFlow Hub からダウンロードされ、以降はプロセス内にキャッシュされます。完全オフライン環境で使う場合は
別途モデルをローカルにホストする対応が必要です。

**精度についての重要な注意**:

1. **個人識別はしていません。** 顔検出は「顔があるかどうか」のみを判定し、「誰の顔か」は判定しません。特定の人物(母など)だけを
   検出したい場合は事前に顔写真を登録した顔認識が必要ですが、精度・誤認識のリスクが高いため今回は採用していません。
   汎用の顔/人物検出結果を人間が最終確認する設計です。
2. **フレームサンプリングの限界。** 全フレームを解析すると重いため、既定では約0.3秒間隔で間引いて検出します(`.env` の
   `DETECTION_SAMPLE_INTERVAL_SEC` で調整可能)。一瞬(サンプル間隔より短い時間)の映り込みは検出漏れの可能性があります。
   **手動区間指定は必須のセーフティネットとして使ってください。**
3. **誤検出・検出漏れが起きやすい条件。** 動きブレ、逆光、横顔・後ろ姿、部分遮蔽、画面内で小さい人物は検出精度が落ちます。

## アーキテクチャ概要

- `src/db/` — better-sqlite3 によるデータモデル(`videos`, `detection_jobs`, `candidates`, `edit_decisions`, `edit_log_runs`)
- `src/services/detection.ts` — フレーム抽出→顔/人物検出→候補区間へのクラスタリング(非同期ジョブ)
- `src/services/pipeline.ts` — カット決定を適用して最終動画を生成し、カットに応じた時間再計算(`edit_log_runs.timeline_mapping`)を保存
- `src/services/youtube.ts` — OAuth2 認証とYouTube Data API v3への動画アップロード
- `src/public/` — フロントエンド(素の HTML/CSS/JS、タイムラインUI・区間レビュー)
- `起動.bat` — Windowsでコマンド操作なしに使うための自動セットアップ+起動スクリプト

`edit_log` は動画1本につき、保存されている `edit_decisions` の集合 + 直近の `edit_log_runs`(パイプライン実行結果と
タイムライン再計算)で構成されます。

## 既知の制限

- 動画は1本ずつ処理する設計です(バッチ処理は未対応)
- 検出・パイプライン処理はサーバー内の単一プロセスで実行されます。大量の動画を同時処理する場合は別途ジョブキューの導入を検討してください
- ぼかし処理はこのアプリの対象外です(YouTube Studio側で実施)
- `npm audit` で報告される脆弱性のうち、`@tensorflow/tfjs-node` のネイティブバイナリ取得用ツールチェーン(`adm-zip`/`tar` 経由)と
  `googleapis` の依存(`uuid`)に関するものが残っています。いずれもインストール時ツールや外部通信ライブラリの内部依存であり、
  修正には両パッケージの大幅なメジャーアップデートが必要なため、影響を確認の上で計画的に対応してください。
